# 同一个飞书机器人换电脑

## 1. 切换前准备，不影响旧电脑在线服务

- 下载完整源码，安装 Node.js 24 LTS，运行 `install.bat`；先做 `npm test` / `npm run check`。
- 从飞书开发者后台取原应用的 App ID 和 App Secret，仅在新电脑本机管理员密码框输入，不发聊天、不写源码/命令行。
- 记录需要重新配置的客户分组别名、单次额度策略与准确目标群。原约定为单次最高20、个人每日/全群每日留空不限；日累计不限会持续累计发放总额，单次限制不是总支出上限。
- 保留旧电脑的完整原件，不把用户目录、浏览器缓存、账本或密文加入 GitHub。GitHub 只传输程序，不转移旧创建记录。
- 新电脑需要使用有平台管理员权限的账号重新授权，普通群成员仍不用登录平台管理员账户。

## 2. 非幂等业务切换检查

- 先请群成员暂停申请，等待正在处理的请求结束；旧电脑若有 pending/unknown，保留账本，按平台权威列表只读核对。不因为新电脑是空账本就判定旧申请没创建。
- 此仓库不提供历史状态、额度累计、密钥回执跨机导入；如必须保留可查询历史，应另做受控迁移并在隔离环境验证，不能复制DPAPI密文后删除报错文件。
- 未完成申请不能跨进程/跨电脑恢复；旧卡片不可继续使用，切换后重新 @机器人发起。
- 当前互斥锁仅在单台电脑有效；同一 App ID 下两台长连接可能竞争事件，不能靠相同应用配置实现可靠切换或去重。

## 3. 正式切换

1. **在旧电脑正常退出业务令牌工具**，确认原连接关闭。保留程序与数据，暂不卸载。
2. 新电脑双击 `启动飞书机器人.bat`，管理员页「登录／重新授权」，在平台页面亲自登录后点「完成登录并保存」。确认实际管理员账号正确。
3. 「重新读取平台分组」，为允许客户选择的分组填写名称并保存，未命名分组隐藏。不要猜原始分组ID。
4. 管理页填同一飞书 App ID、App Secret，点「加密保存飞书配置」；再点「连接飞书」等待「已连接」。保存新凭据会关闭群策略、清除本机旧绑定，这是正常保护。
5. 点「绑定管理员身份」，仅管理员本人按窗口本次显示的完整命令私聊原机器人，再在本机「确认此管理员」。旧电脑的挑战码不可复用。
6. 点「绑定 2API 目标群」，按窗口当前指引在准确的原群发起挑战，再回本机确认群绑定。不要添加到其他群代替验证。
7. 填单次额度上限，按需要设置日上限；按既定策略留空代表明确不限，勾选允许此群所有成员并「保存安全策略」。
8. 分别确认授权可用、账户匹配、飞书已连接、管理员绑定、准确群绑定、全群申请开启；不是只看一个绿色连接标签。

无需新建机器人、重新入群或仅因换电脑发布飞书版本；若后台权限/可见范围另有变化，须按飞书规则另行核验。

## 4. 切换验收

1. 原群 @机器人，验证能够收到私聊菜单。
2. 「用户注册」应为有输入框的卡片，不是在聊天框发送密码；填写专用密码，核对页不显示密码。真实创建仅按实际需要确认一次。
3. 「令牌创建」核对分组与额度，仅发起一次实际需要的申请；不要为测试重放旧创建。
4. 对照平台最终状态、创建记录及私聊收件；报错仅反馈安全错误编号，不发送完整响应或密钥。超时不等于未创建，不能自动重试。
5. 确认重开后的授权和配置仍可恢复；重开前先征得明确同意，连接成功与重新启用分别核验。

## 5. 常开和回退

- Windows 电源设置为接电不休眠，保持网络；锁屏可用，注销会停止。程序目前须手动连接，无自动值守服务保障。
- 本仓库不自动创建开机启动、关机任务，也不修改系统电源策略。
- 新机异常时先停新机连接，保留新机可能新增的创建记录并核对 pending/unknown，再恢复旧机；**不能在新机已创建业务后盲目回旧账本继续发放**。
- 旧历史和新创建记录分属两机；没有统一核对前不宣称历史连续或额度累计完整。
