# 账号管理与一次性调度切换

本机管理员侧边栏「账号管理」读取 [平台账号页](https://max.cheapi.cc/admin/accounts) 的账号列表。每条计划选择两个不同的账号，分别指定“打开调度”和“关闭调度”的目标，并选择先开后关或先关后开。第一步和第二步各填写完整的北京时间 `年-月-日 时:分`，可同一分钟按顺序执行，也可跨日、跨月；一条计划只执行一次。可保存多条计划。

## 操作

1. 确认本机管理员授权有效，在「账号管理」点「读取平台账号与计划」。页面只显示账号 ID、名称、平台、状态和当前 `schedulable` 开关，不下发账号凭据。
2. 选择要打开和要关闭的账号、执行顺序及两次的北京时间，然后点「保存并启用计划」。首次执行至少在当前时间 1 分钟后，第二次不得早于第一次；最多提前两年。同一账号在相邻 5 分钟内不能有另一条未完成计划。
3. 程序保持运行、电脑不休眠并保持平台管理员授权。主进程每 10 秒检查到期计划，最多串行处理 10 个到期步骤。每一步先只读回查；若已是目标状态，不再发送修改；否则先落盘 `attempting`，再提交一次开关请求，最后回读确认。只有第一步确认完成后才处理第二步。
4. 计划可取消尚未执行的步骤；已完成或结果不明的步骤保留。结果不明时只读回查当前状态，若符合目标可标记完成；不会自动重发请求。修改计划时取消旧计划并新建。

## 接口、授权与数据

- 当前平台公开前端资源于 **2026-11-03** 核对：账号列表 `GET /api/v1/admin/accounts?page=N&page_size=100`，详情 `GET /api/v1/admin/accounts/{id}`，开关 `POST /api/v1/admin/accounts/{id}/schedulable`，请求体仅 `{ "schedulable": true|false }`。来源为平台[账号页面](https://max.cheapi.cc/admin/accounts)与当时加载的[前端脚本](https://max.cheapi.cc/assets/AccountsView-rFgvCg5U.js)；仅提取接口契约，不复制代码、素材或页面。这是对现有页面客户端行为的核对，真实服务器响应和开关生效仍需本机管理员验收。
- 请求走现有 `https://max.cheapi.cc` Bearer 管理员授权，发送前再次核验 `GET /api/v1/auth/me`，固定同一管理员账户、目标账号 ID 和本次执行状态；不使用浏览器 Cookie 代替管理员身份。账号列表分页至多 50 页/5000 条，重复 ID、总数变化、缺页及不完整详情均拒绝。
- 计划与执行状态位于当前 Windows 用户的本机加密追加日志，不进入 Git；损坏、无法解密、写入失败都停止执行并保留原件。不会存平台账号凭据、原始接口响应或授权 token。
- 当前限制为最多 100 条计划、单次读取最多 5000 个账号；达到上限须先人工整理、评估迁移，不能删除结果不明记录来腾位置。

## 错过时间与回退

- 到期后最多容许 5 分钟执行偏差。停机、休眠、网络或授权故障超过该窗口会标记“已错过”，不在重开后补做；若第一步错过，第二步取消。临近执行时须检查计划和系统时间。
- 修改请求已经尝试但回执或回读不确定时标记“结果不明”，停止同一计划的后续步骤；重启后残留 `attempting` 也转为结果不明。管理员应先在平台核对真实开关，再决定是否只读回查或另建计划。不要清理日志后重试。
- 这项功能只改变 `schedulable`，不修改账号 `status`、凭据、模型、余额或平台内其他自动调度设置。若其他管理员或平台机制同时操作同一账号，最终状态以平台现场为准；本机计划不是跨电脑互斥或高可用定时服务。

## 验收边界

本地测试使用虚构账号和受控时间，覆盖跨月、先开后关/先关后开、相同时间的多计划串行、异常回执、重启恢复、取消、加密日志和 Electron 管理页。真实平台账号读取及计划到点执行尚未运行；正式使用前应先用非关键账号做一次受控验证。参考的是平台自身公开前端的接口形状，没有复制其代码或素材；其接口若改变，须重新核对。
