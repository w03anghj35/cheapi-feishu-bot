# 充值查询与操作日志核对

本功能面向本机已完成平台授权的管理员，用于逐笔查看平台用户的余额历史，并对照平台操作日志核查“谁给谁调整了余额”。它只读，不提交充值、扣减、清空日志或其他业务操作。管理员账号平台用户 ID 尚待管理员提供；本次输入只用于查询核对，不作为持久配置。

## 数据来源与证据边界

| 数据 | 读取方法与路径（统一前缀 `/api/v1`） | 可确认内容 | 不能由此确认 |
| --- | --- | --- | --- |
| 管理员身份 | `GET /auth/me` | 当前账号 ID 与管理员角色 | 历史某笔操作人 |
| 用户目录 | `GET /admin/users?page=N&page_size=100` | 当前用户 ID、邮箱、用户名 | 历史更名时的名称 |
| 充值历史 | `GET /admin/users/{userId}/balance-history?page=N&page_size=15` | 流水 ID、类型、金额、时间及当前目录对应的收款用户 | 操作人、对应审计日志 ID |
| 平台操作日志 | `GET /admin/audit-logs?page=N&page_size=20&q=…`，必要时 `GET /admin/audit-logs/{id}` | 审计事件 ID、操作人、请求方法、目标路径、时间及可用的请求字段 | 与某笔余额历史的唯一关联、最终生效金额 |

请求使用本机保存的目标平台管理员授权，由 Electron 主进程加 Bearer 认证发起；渲染器没有令牌，也不能拼任意 API 路由。每次查询先核对 `/auth/me` 的账号及 `admin` 角色，读取前后复查授权范围。只允许固定的 GET 路由；管理员余额调整的 `POST /admin/users/{id}/balance` 不属于本功能可调用接口。单次请求超时 30 秒；失败、授权变化或分页不完整时不输出“全部已核对”的统计，不静默跳页或自动重试。

`admin_balance` 正值标为管理员正向充值，负值标为管理员扣减；兑换码余额、推广余额、订阅额度与并发类记录分别标注，不能一概算作管理员给他人充值。低于 10 的小额按**单笔正向管理员充值**判断，等于 10 不算小额。汇总金额沿用平台余额单位，不用当前余额倒推充值额。页面默认按照流水时间逐笔排列，可在本次结果中按收款人、类型和编号筛选。

金额按平台余额字段的 **8 位小数**口径处理：接口 JSON 可能给出 `float64` 数值，并带有二进制浮点尾差或科学计数法。主进程只在可确认为该口径的数值时规范化成十进制字符串，汇总与 `<10` 判断使用固定刻度整数运算；管理页按规范化字符串显示最多 8 位小数，不再把金额转回 JavaScript 浮点数求和。明显超出平台精度、非有限、缺失或非零却小于最小刻度的金额仍会停止完整查询，不会记为零、跳过该笔或悄悄截断；错误只显示用户 ID、页码与页内序号，不回显原始金额或备注。推广转入记录在上游会用负整数作为合成流水 ID；仅该类型接受此编号，仍参与分页去重。

**两端目前没有已确认的逐笔关联键。**余额历史未见审计 `request_id`/事件 ID，审计日志也未见余额流水 ID。因此即使目标用户、金额和时间接近，也只能作为“候选证据”，不能自动填入该笔充值的操作人。日志中的余额调整请求本身可以独立展示其操作人、目标用户和请求值；HTTP 状态与最终入账仍须与平台实际余额历史人工核对。未经可靠逐笔归因，管理员给自己充值的剔除额、给他人的净额与给他人单笔低于 10 的统计应显示“待确认”，不能把未知当 0。管理员账号 ID 提供后也不能替代关联证据。

审计证据与充值流水分成两个列表。审计行只投影事件 ID、时间、目标用户、操作人 ID/邮箱、请求操作类型、**请求值**、HTTP 状态与请求 ID 等明确字段；“请求值”不是已确认实际入账额。上游列表在平台标准 `{code,data}` 外层下的 `data` 为 `{items,total,page,page_size,pages}`，本机请求适配器先解开外层；详情的 `request_body` 是可能已脱敏或截断的 JSON **字符串**，不能假设总能解析出完整金额或操作类型。审计读取不完整时，界面会标出原因并停止据此得出全量结论；详情内容无法安全解析时，请求操作与请求值留空。

## 分页、限额与隐私

本版用户目录按 100 条逐页读取，最多 50 页；余额历史逐用户按 15 条逐页读取，最多 40 页。一次最多扫描 200 位用户、累计 3000 条流水或 5 分钟；超过上限提示按准确用户 ID 缩小范围。审计列表按 20 条逐页读取，最多 10 页、200 条详情，超出上限时明确标记审计不完整。遇到页数、总数、重复编号或响应结构异常，停止并拒绝完整汇总；不把部分日志称为完整核对。

界面只显示核查所需的用户 ID、当前用户名/邮箱、流水类型/金额/时间与审计白名单字段。审计详情中的原始 `request_body`、`extra`、Cookie、Authorization、备注及完整响应不写入本机操作日志，也不直接透传到渲染器；只解析明确允许的金额、操作类型和目标 ID。查询结果留在本次窗口内存中，管理员离开或关闭窗口后不应当作可恢复账本。不要把真实截图、账户数据或浏览器分区提交到仓库。
