# 用户余额

管理端第 14 栏「用户余额」点击「读取全部用户余额」后，分页读取平台当前用户目录，显示用户 ID、用户名、邮箱、角色、状态、余额以及是否计入汇总。列表按余额从小到大排列，关键词可筛用户名、邮箱和 ID；每次先显示 100 行，可继续展开，筛选或只显示前 100 行均不会改变顶部的全量合计。

## 合计口径

- **普通用户正余额合计**：仅累加平台 `role=user` 且 `balance>0` 的用户。正常、停用、未激活的普通账号按同一规则计算。
- 平台 `role=admin` 的所有账号排除，另显示排除的管理员人数及其正余额合计，不只排除当前登录管理员。
- 普通用户零余额和负余额保留在明细，不计入正余额合计，负余额不抵扣正余额。角色或余额无法验证时停止整次查询，不猜角色，不跳过异常记录或补零。
- 按管理员确认的业务口径将平台 `balance` 视为人民币 CNY（接口本身未逐用户返回币种），最多八位小数。求和及排序采用八位定点整数；只累加普通用户正余额，普通用户负余额另列，不混入渠道原始金额。财务现金接口中的 U 余额才单独按其规则折算，不能把客户余额误乘 6.65。

## 接口与权限

只使用主进程保存的当前管理员 Bearer 授权，调用 `GET /api/v1/auth/me` 和 `GET /api/v1/admin/users?page=N&page_size=100`。每页返回 `items,total`，只投影 `id,email,username,role,status,balance`。首次和结束复核管理员身份与角色，生产请求适配器对每个管理员 GET 再核对授权；渲染器不接触令牌，IPC 只允许管理员入口主框架。无需飞书目标群或用户归属，查询不发送飞书消息，不修改平台余额。

每次最多 50 页/5000 用户，服务总时间上限 2 分钟（检查发生在请求前后，单次网络超时 30 秒）。逐页验证唯一 ID、稳定总数及页完整性。并发点击拒绝重复全量查询；网络或分页失败不输出部分合计，不自动重试，管理员可手动重查。空目录经完整读取后显示 0 个账号与 0 合计。

界面展示读取开始和完成时间（北京时间），不是服务器事务快照；充值或消费发生在分页期间可能使不同用户读数对应不同瞬间。八位规范化与定点汇总也无法恢复源接口 JSON number 已损失的精度。结果仅留本次窗口内存；重新读取前清旧结果，授权失效时清结果并拒收迟到响应。操作日志只记动作、状态和安全错误码，不保存账号清单、金额或原始接口响应。
