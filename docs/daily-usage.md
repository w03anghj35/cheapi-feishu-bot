# 归属用户每日用量群表

群表只发当前绑定目标群，按用户实付金额 `total_actual_cost` 统计，逐账号显示邮箱与用量；每位归属人一张最近 3 天的滚动日表。旧版约每小时更新已有群卡片（不是每小时新发一张），2026-11-07 用户确认已实际收到群卡片后，要求改为**管理员设定北京时间、每天最多更新一次**。本次新逻辑已在源码实现，正式运行实例尚未重载，不能把本地测试称为在线生效。

## 管理端历史周表

2026-11-07 修正采样与群发布的关系：此前自动用量读取被群卡片发布开关阻断；换版前只读账本确认 11 月 1–5 日仅有手动补采，6 日与 7 日均无自动快照，群表也没有启用记录。因此管理端看不到新日期，不是表格滚动或邮箱显示问题。新版在平台管理员授权、原目标群绑定和归属档案存在时，**本机历史独立约每小时只读采样**，群卡片仍默认关闭、绝不因本机采样自动发群。启动后与每分钟调度检查一次是否到期；跨日先补读昨天再读今天，昨天若按当前归属补读，标记「回填」，不冒充昨日真实归属。空档案、授权缺失、平台读取/存储失败不会写虚假的零金额；失败至少等约 15 分钟再试。管理端新增采样状态与最近已存日期提示，打开历史页后每分钟检查最新快照并在变化时自动重绘表格，筛选选择不丢失。换版后管理员亲自恢复授权，原目标群和平台账号核验通过，11 月 6 日完整日与 7 日进行中快照已加密落盘且在周表显示；下一小时更新与长期运行仍待观察。

管理端独立侧栏「用量统计」提供 Excel 风格的只读表格，按「月份 → 周 → 所属人」下拉筛选。周从北京时间周一到周日，跨月的周会同时出现在相邻月份的选项中。表格逐平台账号邮箱展示 7 个自然日的用户实付、每日合计和每周合计；未采集日显示“未记录”，未来日显示“未到”，当天未结日显示“进行中”。某日只有部分账号有快照时，当日合计标“小计”；只有七天及该账号的七个值均已固定，才标为完整周总额，否则明确显示“已记录小计”。同一平台用户若归属多个姓名，按各自档案分别展示，不在单张表中串入其他归属人的邮箱。

管理端可自选北京时间开始与结束日期，默认当前周，分别点「导出当前归属人」或「导出全部归属人」。保存对话框由管理员选择本机 `.xlsx` 位置；全部归属人导出为一张可筛选的「用量明细」工作表，包含日期、归属人、平台用户 ID、邮箱、用户实付、归属人当日合计、日期状态、合计口径、采集来源和采样时间。日期、金额为可排序的 Excel 日期与数值；账号缺失或未采集时金额留空，真实零金额为数字 0。每日合计仅在该归属人该日第一行出现一次，防止逐账号行重复加总；进行中标为「已记录小计」，回填标明「按当前归属回填」，不能据此断言历史归属。缺日、未来日会有状态占位行，但不会凭空生成账号用量。每次最多导出 366 天、150000 行，超限请缩短范围；导出不查询平台、不发群、不改账本。文件含平台邮箱，请只保存在受控位置，不上传公开仓库。按钮须重新加载管理端页面后出现；真实管理员导出文件仍待现场验收。

横向滚动日期时，表头、账号行和合计行的第一列固定在左侧，便于对应邮箱与金额；上方“归属人 · 日期范围 · 用户实付”标题位于滚动区外，也不会被横向带走。表格仍通过该标题提供可访问名称。这只改变管理端表格呈现，不修改历史快照、统计口径或群卡片。此界面改动须重新加载管理员窗口才会出现；如有未保存的归属草稿，先核对加密暂存状态，不能为看新样式直接重启业务实例。

下拉月份来自当前月和本机加密账本已有快照月份；无历史时也可打开当前周空表。管理员 IPC 需先通过平台授权和当前管理员/群范围核对，目录只传月份与归属姓名，表格请求只传一个归属人、一周的必要明细，不将整份历史账本发给界面。普通查看本身不请求平台；后台约每小时只读采样今天并在跨日补读昨天，其他本月旧日期仅在管理员明确点击补采按钮时查询。该视图不会发群，也不改变群卡片最近 3 天的规则。启用前或停机期间未采集的更早日期不会凭空出现；32 MiB 账本上限仍在，所谓“不限三天”仅指管理端没有三天展示截断。归属修改或邮箱变更后，旧快照仍按采集时的姓名与用户 ID 保留，表中邮箱显示该周最后一次采样的值。历史快照没有独立档案 ID；若删除后将同一姓名用于另一个人，两段历史可能无法区分，应避免重用归属姓名。真实平台金额、结算日口径和长期账本容量须在正式环境继续核对。

管理员可在「用量统计」明确点击“补采本月已结束日期”。程序只从当前北京时间月的 1 日查到昨天，使用现有管理员 Bearer 授权与固定 GET `/api/v1/admin/usage/stats?user_id={正整数}&start_date={日期}&end_date={同日期}`，逐日按当前已保存归属账号查询用户实付 `total_actual_cost`；单日去重后最多 2 个平台只读请求同时进行，相邻请求启动仍间隔约 200ms，仍受 150 个不同用户、30 个归属档案、120 秒读取预算约束。已有完整日快照跳过，不覆盖；每一日全部账号成功且管理员、群和归属未变化才将整日快照追加到本机加密账本。失败当天不落部分数据，之前成功日期保留，再次点击会从缺失日继续。单次总时限约 10 分钟，超时后可再点续采。补采不更改群发布开关，也不直接调用飞书消息接口。

补采快照带“按当前归属回填”来源标记，周表日期标题显示“回填”。这只表示平台在补采时返回该用户对所选日期的统计，**不能证明该账号在当日已属于现姓名档案**；若历史归属曾改变，应按平台和归属审计另核。平台统计接口的结算时区与旧日期响应仍待用正式账号对照页面验证。没有历史账本时，首次补采会创建新的本机加密账本；不得把它当成旧程序原本已保存的历史。

## 已核对的外部页面契约

2026-11-05 只读检查 `https://max.cheapi.cc/admin/usage` 当前公开前端资源：用户筛选先按邮箱搜索并取得稳定 `user_id`，用量统计走 `GET /api/v1/admin/usage/stats`，传 `user_id`、`start_date`、`end_date`；统计卡片分别展示 `total_actual_cost`（用户实付）与 `total_cost`（标准成本），不能混称。当前项目已有归属平台用户 ID，无需再以可变邮箱重新定位。这个结论是客户端代码契约，真实授权响应与时区口径尚未通过管理员账号现场验收；上游可改版。

`key-tool/daily-usage.js` 对每位被归属的普通用户形成固定日期的只读查询路径，严格检查 `total_actual_cost` 为有限、非负数值；同一用户 ID 即使出现在多个档案也只查询一次。无账号、缺字段、未来日期、管理员/目标群/归属变化、超过 30 档案/150 用户上限或 120 秒总读取预算，均拒绝返回不完整的表。日期键用北京时间自然日。例如 2026-11-23 从北京时间 00:00 至 2026-11-24 00:00 归属于 23 日，客户端接口以 `start_date=2026-11-23&end_date=2026-11-23` 表示该日；是否与服务端结算时区完全一致还须用实际页面同日期对照。

## 管理端操作与群可见性

在「用户归属」下方的“归属用户每日用量”点“预览今日用量”，会使用当前平台管理员授权只读读取，展示每位归属人及邮箱、今日用户实付和合计；**预览不发群**。请先对照平台用量页同一用户、同一北京日期的 `total_actual_cost` 与单位，确认站点结算日语义一致。填写“每日群卡更新时间（北京时间）”后点“保存时间并启用定时群表”，再次确认全群可见的邮箱与用量；保存操作本身不立即发群。若保存时所选时刻尚未到，今天该时刻生效；若已到，次日才生效。程序只在设定时刻后的 15 分钟窗口尝试，当天错过不追发；同一归属人当天成功发布/更新后，即使改时间或重启也不再重复发。旧账本即使已有 `enabled=true`，缺少本次新增的每日时刻时也停止自动群发，须管理员明确设时。设置时间前仍须预览有归属用户；主进程再核验管理员、群、连接与策略。“暂停群发布”只停后续更新，不删除或撤回已发卡片。

一张卡片对应一个姓名档案，列出当前归属账号邮箱、最近 3 个北京自然日及每日合计。当天标题有 `*` 并标“今日进行中”；次日采样会补读并固定昨天金额，随后开始今天新列。历史中没有成功读取的日子显示“—”，**不是零**。档案被删或清空时，群表启用、连接可用且没有待核对消息的条件下会尽快尝试把原卡片更新为“不再公开”，这是隐私优先的非定时例外，仍可能产生一次更新通知；只从同一档案移除单个账号时旧卡可能保留到下次设定时刻，若必须立即隐藏，管理员应在飞书原群人工处理旧消息，**暂停群发布不会撤回旧卡**。群成员此前看到或截图的内容也无法撤回。单卡最多 30 个账号、UTF-8 JSON 不超过 28 KB；超限不发送不完整表格。卡片每 10 天轮换成一张新卡，以降低旧消息更新失败风险；此前卡片留在群里，不会自动删除。

## 定时、持久保护与失败处理

本机历史独立约每小时只读采样；群发布每分钟只检查是否进入管理员设定的每日时窗，不能把本机新快照当成群已更新。群卡片创建与更新继续逐张串行，一张结果不明就停止后续群发送。程序停机、休眠、断网、授权失效或飞书未连接时不发送；错过当天时段不追发。群发布需最新完整当日读取，跨日会先补读上一日（若原来仍是进行中）。不新建 Windows 定时任务。底层接口只允许固定 `GET /api/v1/admin/usage/stats?user_id={正整数}&start_date={YYYY-MM-DD}&end_date={同日期}`，使用现有管理员 Bearer 授权；去重后最多 2 路只读并发，相邻请求启动约间隔 200ms。响应只取 `total_actual_cost` 等白名单字段，不记录 token、原始响应或请求明细。任何一个用户读取失败或超时，本轮等待已在途只读请求结束后整体失败，不发布部分表格，也不因失败立即重试限流响应。

## 群内入口与按需私聊

目标群成员先在**原绑定群** @机器人，再在机器人私聊菜单点「用户用量」。这与「用户查询」余额菜单分开；新菜单只接受已由管理员核对、按稳定飞书身份绑定的本人归属，不依据可更改的显示名或手输姓名查别人。未绑定者会被提示先点「用户查询」登记，再由管理员在「用户归属」绑定。用量查询不受群表每日时间/发布开关影响：今天对本人归属账号做一次完整只读查询，前两日只从本机已固定的加密快照取数，缺失或尚未固定显示“—”，不当作零或最终用量；结果只发给发起人的飞书私聊，不发群。查询期间如管理员、绑定群、身份归属或北京自然日变化，整轮停止，不发送旧结果。后台限制同时仅一笔私聊用量任务，以免慢查询阻塞其他注册/令牌菜单。最近查询记录加密标记「用量」与查询状态；读取成功不等于私聊已送达，回执不明不自动重发。真实私聊卡片渲染及平台日期口径待现场验收。

本机 `%APPDATA%/CheapiKeyStudio/daily-usage/daily-usage.journal` 用 Windows `safeStorage` 加密追加保存开关、当日快照及每档案群卡片状态。创建群卡片或更新旧卡片前，再核对管理员、目标群及当前归属；若读取后归属变化，拒绝发送旧邮箱。发送前先持久记录尝试，确认飞书回执后记录消息 ID；发送结果不明或重启留下“尝试中”时，**全部群表自动发布暂停**，管理员需先到目标群核对，不能靠重启或再次点启用绕过。平台读取失败后至少等待约 15 分钟再尝试，避免每分钟反复打接口；存储故障则关闭发布、保留原件，不作自动修复。存储损坏或达到 32 MiB 上限时群发布关闭且保留原件。该密文不进入 Git，也不能跨电脑直接解密。

2026-11-07 的首次群卡片发送留下了一笔无消息 ID 的“结果不明”，旧版没有保存具体错误码；飞书后台同时间窗未检索到发送调用，但“无日志”不能证明卡片一定未送达。新版（**本地已实现，正式运行实例尚未重载**）只为首次创建的 `unknown/attempting` 提供「记录未见并暂停（不发送）」：管理员先在原绑定群按归属姓名及北京时间逐条核对，勾选本人核对声明，再在默认取消的系统确认框核对群摘要与尝试时间。主进程两次验证管理员及准确群；同一条加密事件原子保存“人工记录未见”并关闭群发布，不删除原 `unknown` 或自动发送。重复、过期、异群或旧消息更新结果不明均拒绝此入口。之后必须重新预览邮箱与金额、再次明确启用，才会尝试新的首次发送；如果人工漏看旧卡，仍有重复公开风险。飞书发送 API 不支持依赖 UUID 幂等重试，因此不能把解除保护当作“已证实未发送”。

新版对**以后发生**的群卡片失败仅加密记录白名单诊断：本机预检／飞书 API 拒绝／HTTP／超时／网络／回执不完整／未分类，以及可用时的 HTTP 状态码和飞书数字错误码；不保存原始异常、完整响应、请求正文、密码或 token。现有 11 月 7 日旧记录无法凭升级补出历史错误码。发送仍走应用身份 `POST /open-apis/im/v1/messages?receive_id_type=chat_id`，只发送到原绑定群；本轮实现未向真实群发送，也未人工解除现有待核对记录。

飞书消息使用现有应用身份：`POST /open-apis/im/v1/messages?receive_id_type=chat_id` 仅发送到当前绑定群；后续 `PATCH /open-apis/im/v1/messages/{message_id}` 更新同一张非交互卡片。卡片仅含纯文本，禁转发、无表单或按钮。消息发送/更新失败不保留完整服务端异常；群里看到的实际渲染、旧卡片更新可用期和应用权限须在真实小范围验收。**本地隔离测试只证明代码和模拟回执，不证明正式群已收到或结算金额正确。**
