# 渠道授权首版（本机隔离原型）

版本标识：2026-11-07 本地增量，未换版上线。

## 目标与范围

面向本机管理员，为将来已核验的机器人账号与成员稳定身份分配“可查看哪些渠道”。本版新增独立侧边栏“渠道授权”，实现加密保存、更新、撤销与本机只读预览。它不接入 CodexBridge、微信或 AI，不发送消息，也不改变现有邮件提醒和飞书业务。

之所以单独设栏，是因为授权有按人列表、渠道勾选、撤销和预览，不适合挤入已有五张余额卡及邮件配置。栏目仅为管理便利；真正的查询判断在主进程存储模块，不能依赖前端隐藏。

## 管理操作

1. 将来从可信入站消息核对机器人账号标识和成员稳定标识。当前界面允许手工录入以支持隔离原型；尚无扫码绑定及身份认证流程，所以**不能仅凭成员提供的字符串认定已绑定**。
2. 填写管理员易识别的显示名称，勾选至少一个渠道，点“加密保存授权”。默认没有任何授权。
3. 已配置成员可更改可见渠道、撤销或重新启用。不能选择空渠道保存，避免意外把“无权限”和“配置漏填”混为一谈；应使用撤销。
4. “只读预览”按该成员权限过滤当前监控内存快照；读取失败、正在读取或超过一小时的旧读数显示“未取得”。不触发网站访问，也不发送消息。

配置位于当前 Windows 用户应用数据下 `channel-monitor/channel-access.journal`，经 Electron safeStorage 加密后追加保存。存储读取损坏或加密后端不安全时拒绝查询与修改，保留原件。不要把此文件复制到其他 Windows 用户/电脑并假设能解密；不加入仓库。

## 后续桥接契约

`channel-access.js` 提供 `queryCurrent({botAccountId,senderId}, getSnapshots, options)`；身份参数**必须由可信聊天适配器从入站事件取得**，不能由用户文本、模型调用参数或公开 HTTP 请求体提供。该方法重新检查授权后只返回白名单渠道的名称、指标、有效数值与时间。查询不能直接调用全量 `channelMonitor.state()` 后交给 AI 过滤。

下一版对接 CodexBridge 前还需：确认项目代码使用许可；完成扫码绑定与身份核验；收紧其跨用户线程列表/打开、可切换 full-access 等命令；为桥接进程设计受认证的本机查询通道和状态保护；在真实微信账号下验收问答和主动通知。当前首版没有执行这些步骤。工作区不能把前端预览接口当普通用户查询接口。

## 验证与已知限制

合成测试覆盖两人不同权限、跨人拒绝、机器人账号不匹配、撤销与重开、旧读数、损坏文件、不安全加密后端和授权文件意外消失；隔离 Electron 小界面夹具覆盖保存、预览、更新、撤销。未真实连接微信、CodexBridge、AI 或线上渠道。

完整 `npm run test:ui` 多次运行中既有45秒总时限超时，也有完整通过，提示该全页面夹具耗时不稳定；通过的运行报告真实网络请求与业务创建请求均为0。新栏的独立 Electron 小夹具稳定通过。当前管理页加载到真实长期运行实例的效果仍待经授权换版后验收。
