# 飞书自动连接与断线恢复

更新日期：2026-10-31。

## 行为

- 业务主程序启动后自动启用连接守护；保存过飞书凭据且平台授权可恢复时自动连接，不必每次点连接按钮。不创建Windows开机任务，程序仍须运行。
- 主进程每5秒检查真实SDK状态，不依赖管理窗口是否打开、显示或获得焦点。
- 单次连接/SDK重连仍有45秒截止；失败后安全关闭本轮连接，再约5、10、20、40、60秒退避重试，之后每轮等待最多60秒，不设总重试次数上限。检查周期可能增加最多约5秒调度延迟；单次连接耗时另计。短暂上线不清零退避，稳定在线60秒后清零。
- SDK尚在连接时不另开连接；关闭失败或锁状态不明时停留保护状态，不强杀、不删除锁。其他实例持锁时只等待重试，不抢占。
- 点击“断开飞书”暂停本次运行中的自动连接，并取消在途授权完成后的迟到连接；点击“连接飞书”恢复。退出应用停止全部守护定时器；下次启动重新启用。
- 保存新凭据会暂停守护并沿用原来的清空绑定规则，保存后点击连接恢复。不要为刷新状态反复保存Secret。
- 未配置凭据、存储错误或旧连接未安全停止时，显示具体待处理状态；没有有效凭据不能凭空连接。平台授权失效时等待管理员重新授权，不绕过核验；网络恢复后继续检查。
- 只恢复通道，不重发注册、令牌创建、倍率更新或密钥消息；pending/unknown及原群策略不变。

## 为什么以前会停在失败

当前锁定飞书SDK本身支持自动重连，但业务封装遇到onError或45秒连接截止会关闭SDK，并要求手动重试。旧管理页状态轮询还会因隐藏窗口停止，因此仅打开SDK的autoReconnect不等于应用能持续恢复。

本次在业务主进程增加`feishu-reconnect.js`，单独管理连接意图、退避、授权恢复和守护定时器；`feishu-connection.js`保留单次生命周期与安全关闭职责。独立诊断工具仍保持手动连接，避免诊断窗口自动竞争正式连接。

截图无法证明某次断线的网络/服务端原因。本次只确认了原代码失败后停止恢复的行为；没有读取原始SDK错误、凭据或敏感响应来猜测历史故障。

## 验证

306项Node测试、51项隔离Electron检查、63份语法检查通过。新增测试覆盖：自动首次连接、并发start单实例、指数退避与无限轮次、45秒超时、无界面静默断线、稳定连接清零、手动暂停、退出、授权迟到、凭据缺失、存储错误、锁竞争、关闭失败。真实锁定SDK通过本地WebSocket模拟“失败后替换SDK实例并成功连接”，无真实业务请求。界面验证倒计时与等待期间可停止。

以上故障注入是本地模拟，不等于真实网络断电、休眠或长期运行验收。真实启动自动连接需换版后核验；不保证网络永久故障时仍能在线。平台或SDK要求等待/限流时，不提高并发或绕过限制。

2026-10-31现场换版：正常退出旧实例后启动新版，未点击连接按钮；实际管理页已显示平台授权可用、飞书已连接、原群策略有效及自动连接守护开启。确认启动自动连接成功；未人为切断生产网络，长期真实故障恢复仍待后续运行观察。
