## 从网址到可用监控的步骤

1. 用户指定完整 HTTPS 页面和指标语义。先区分余额、累计消费、今日消费、积分与货币单位；同一个站点的不同数字不能互代。
2. 只读查看未登录路径、登录后路径、页面可见标签和目标组件。官方文档、公开前端资源与实际已登录界面分层记录，不能把公开代码推断写成实测数值。
3. 在 `key-tool/channel-monitor.js` 的 `CHANNELS` 加入固定来源、路径、指标、默认名称和定位器。若已有渠道只是路径或口径更正，保留其稳定内部ID及持久分区，不导致用户重新登录。
4. 在 `observationScript` 仅从匹配来源和页面的可见组件取少量候选字符串；`parseAmount/chooseMetric`负责格式与唯一性校验。页面加载中的占位数不算成功；前后两次观察一致才接受。
5. `key-tool/channel-monitor-host.js`负责本机独立持久浏览器、同源导航和页面观察。`channel-monitor-controller.js`负责启动后首次读取、五站串行、每站约30分钟到期刷新、手动读取、失效时显示旧值时间。
6. `key-tool/admin-channel-monitor.js`负责页面状态和自定义名称；主进程 `key-tool/main.js`只暴露固定ID的管理IPC。增加或变更站点时同步此目录、`docs/channel-monitor.md`、专项测试和隔离Electron界面测试。
7. 用真实本机登录态核验一次指定页面的标签、数值与单位；同一时刻对照网站页面和监控卡片。不记录或传播实际账户敏感数据。随后验证重开应用是否能复用登录态，以及半小时后是否刷新；这些是独立验收，不以单次读取代替。

## 失败与变更判据

- `待登录`：页面稳定停在登录表单。默认不保存密码；管理员可在对应站点卡片独立启用本机加密配置，仅在核对表单后自动提交一次，失败暂停，不反复试错。验证码、二次验证和安全警告交由管理员处理。
- `自动登录表单未识别`且网站窗口已登录：先看该站的直接文档URL是否返回公开首页、真实业务页是否依靠前端路由。不要重复保存密码或用消费金额充当余额；优先从同源已登录应用的侧栏导航到目标页，若确实未登录再用站点正常登录入口。AeroRelay 的这一修复已在本地候选版实现，真实在线读数仍待换版验收。
- `金额未定位`：指定页面没有匹配组件或数值格式不符。先检查对应站点文档的组件位置、精度和最近页面改版，不用附近另一个数字凑结果。
- `位置不唯一`：有多个不同候选；需明确业务口径后缩小选择范围。
- `页面读取失败`：看网络、证书、会话或加载状态；普通站点错误页与 HTTPS 安全警告分开，绝不自动绕过安全警告。
- 站点指标变更：按用户新定义改路径、标签、单位和测试；保留旧值的时间与“当前未验证”状态，不能用旧口径金额当新口径金额。
- 网页HTML、CSS选择器、前端包名和登录策略都可能改动。每次变更记录可靠的执行日期和重新验证范围，不把某次检查变成永久契约。
