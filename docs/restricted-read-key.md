# 平台受限密钥接入：历史记录

2026-11-11 曾为部分平台管理 GET 请求增加独立 `x-api-key` 认证，用户随后确认：原项目本来就直接调用平台 REST API，换凭据不会改变接口、金额计算口径或固有速度，因此要求恢复原网页登录令牌路径。本页仅保留撤回方案的非敏感技术背景，**不是现行配置步骤**；回退状态以 [交付记录](release.md) 最新条目及实际运行版本为准。

曾采用的边界：原管理员网页登录 JWT 仍核验身份，注册、令牌创建、分组倍率写入及其回读也仍由 JWT 承载；新密钥只覆盖用户目录、分组目录、用量统计/明细与余额流水的指定 GET。保存前曾对六类代表性只读接口做有界预检。该设计没有解决 JWT 到期问题，也不比原直接调用平台 API 天然更快。

现场曾创建一枚广权限、无到期日并按两个当时观测的出口 IP 限制的管理密钥。**平台密钥与本机程序是两件事：删除接入代码或停用本机副本不会撤销平台密钥。** 用户后续明确授权永久撤销，平台页面对该目标显示“已撤销”；本机旧加密密文文件仍保留原件但恢复版不加载。创建过程中一次性密钥曾进入工具截图，用户知悉后当时选择暂不轮换；不在本页留存密钥、IP、客户资料或响应原文。

历史接口形状、原有计算和保护应以仍在项目中的业务模块为准，例如 `daily-usage.js` 的按日 `total_actual_cost`、`group-usage.js` 的逐条 `actual_cost` 汇总；恢复原凭据路径不应重写金额算法、业务账本或群发布策略。
