# 归属用户每日用量群表

2026-11-06 已完成本地实现，**默认关闭、在线实例尚未加载，也未向真实群发送**。管理员确认：只发当前绑定目标群，按用户实付金额 `total_actual_cost` 统计，逐账号显示邮箱与用量；每位归属人一张最近 3 天的滚动日表，当天约每小时更新同一张卡片。

## 管理端历史周表

管理端独立侧栏「用量统计」提供 Excel 风格的只读表格，按「月份 → 周 → 所属人」下拉筛选。周从北京时间周一到周日，跨月的周会同时出现在相邻月份的选项中。表格逐平台账号邮箱展示 7 个自然日的用户实付、每日合计和每周合计；未采集日显示“未记录”，未来日显示“未到”，当天未结日显示“进行中”。某日只有部分账号有快照时，当日合计标“小计”；只有七天及该账号的七个值均已固定，才标为完整周总额，否则明确显示“已记录小计”。同一平台用户若归属多个姓名，按各自档案分别展示，不在单张表中串入其他归属人的邮箱。

横向滚动日期时，表头、账号行和合计行的第一列固定在左侧，便于对应邮箱与金额。它只改变管理端表格呈现，不修改历史快照、统计口径或群卡片。此界面改动须重新加载管理员窗口才会出现；如有未保存的归属草稿，先核对加密暂存状态，不能为看新样式直接重启业务实例。

下拉月份来自当前月和本机加密账本已有快照月份；无历史时也可打开当前周空表。管理员 IPC 需先通过平台授权和当前管理员/群范围核对，目录只传月份与归属姓名，表格请求只传一个归属人、一周的必要明细，不将整份历史账本发给界面。普通查看不会实时请求平台；只有管理员明确点击补采按钮才查询本月旧日期。该视图不会发群，也不改变群卡片最近 3 天的规则。启用前或停机期间未采集的日子不会凭空出现；32 MiB 账本上限仍在，所谓“不限三天”仅指管理端没有三天展示截断。归属修改或邮箱变更后，旧快照仍按采集时的姓名与用户 ID 保留，表中邮箱显示该周最后一次采样的值。历史快照没有独立档案 ID；若删除后将同一姓名用于另一个人，两段历史可能无法区分，应避免重用归属姓名。真实平台金额、结算日口径和长期账本容量须在正式环境继续核对。

管理员可在「用量统计」明确点击“补采本月已结束日期”。程序只从当前北京时间月的 1 日查到昨天，使用现有管理员 Bearer 授权与固定 GET `/api/v1/admin/usage/stats?user_id={正整数}&start_date={日期}&end_date={同日期}`，逐日按当前已保存归属账号查询用户实付 `total_actual_cost`；每位用户之间约 200ms，单日仍受 150 个不同用户、30 个归属档案、120 秒读取预算约束。已有完整日快照跳过，不覆盖；每一日全部账号成功且管理员、群和归属未变化才将整日快照追加到本机加密账本。失败当天不落部分数据，之前成功日期保留，再次点击会从缺失日继续。单次总时限约 10 分钟，超时后可再点续采。补采不更改群发布开关，也不直接调用飞书消息接口。

补采快照带“按当前归属回填”来源标记，周表日期标题显示“回填”。这只表示平台在补采时返回该用户对所选日期的统计，**不能证明该账号在当日已属于现姓名档案**；若历史归属曾改变，应按平台和归属审计另核。平台统计接口的结算时区与旧日期响应仍待用正式账号对照页面验证。没有历史账本时，首次补采会创建新的本机加密账本；不得把它当成旧程序原本已保存的历史。

## 已核对的外部页面契约

2026-11-05 只读检查 `https://max.cheapi.cc/admin/usage` 当前公开前端资源：用户筛选先按邮箱搜索并取得稳定 `user_id`，用量统计走 `GET /api/v1/admin/usage/stats`，传 `user_id`、`start_date`、`end_date`；统计卡片分别展示 `total_actual_cost`（用户实付）与 `total_cost`（标准成本），不能混称。当前项目已有归属平台用户 ID，无需再以可变邮箱重新定位。这个结论是客户端代码契约，真实授权响应与时区口径尚未通过管理员账号现场验收；上游可改版。

`key-tool/daily-usage.js` 对每位被归属的普通用户形成固定日期的只读查询路径，严格检查 `total_actual_cost` 为有限、非负数值；同一用户 ID 即使出现在多个档案也只查询一次。无账号、缺字段、未来日期、管理员/目标群/归属变化、超过 30 档案/150 用户上限或 120 秒总读取预算，均拒绝返回不完整的表。日期键用北京时间自然日。例如 2026-11-23 从北京时间 00:00 至 2026-11-24 00:00 归属于 23 日，客户端接口以 `start_date=2026-11-23&end_date=2026-11-23` 表示该日；是否与服务端结算时区完全一致还须用实际页面同日期对照。

## 管理端操作与群可见性

在「用户归属」下方的“归属用户每日用量”点“预览今日用量”，会使用当前平台管理员授权只读读取，展示每位归属人及邮箱、今日用户实付和合计；**预览不发群**。请先对照平台用量页同一用户、同一北京日期的 `total_actual_cost` 与单位，确认站点结算日语义一致。点“启用并首次发布到群”前会再次提示：所有目标群成员都能看到逐账号邮箱与用量。按钮仅在预览有归属用户时可用，并在发送前再核验管理员、目标群、飞书连接与群策略。默认关闭；“暂停群发布”只停止后续更新，不删除已发卡片。

一张卡片对应一个姓名档案，列出当前归属账号邮箱、最近 3 个北京自然日及每日合计。当天标题有 `*` 并标“今日进行中”；次日首次运行时会补读并固定昨天金额，随后开始今天新列。历史中没有成功读取的日子显示“—”，**不是零**。卡片对当前归属账号重建，已从档案移除的账号不再出现在新卡片；档案被删或清空时会尝试把原卡片更新为“不再公开”，但群成员此前看到/截图的内容无法撤回。单卡最多 30 个账号、UTF-8 JSON 不超过 28 KB；超限整轮不发送不完整表格。卡片每 10 天轮换成一张新卡，以降低旧消息更新失败风险；此前卡片留在群里，不会自动删除。

## 定时、持久保护与失败处理

启用后每分钟检查是否到了下一轮，距今日上次成功采样至少一小时才重新读取；所有查询与群卡片更新串行。程序停机、休眠、断网、授权失效或飞书未连接时不发送；恢复后在可用条件下继续，不承诺整点，也不会补齐所有停机历史。每轮最多一次当前日读取，跨日会先补读上一日（若原来仍是进行中）。不新建 Windows 定时任务。底层接口只允许固定 `GET /api/v1/admin/usage/stats?user_id={正整数}&start_date={YYYY-MM-DD}&end_date={同日期}`，使用现有管理员 Bearer 授权；每个用户串行、每次读取后等待约 200ms。响应只取 `total_actual_cost` 等白名单字段，不记录 token、原始响应或请求明细。

本机 `%APPDATA%/CheapiKeyStudio/daily-usage/daily-usage.journal` 用 Windows `safeStorage` 加密追加保存开关、当日快照及每档案群卡片状态。创建群卡片或更新旧卡片前，再核对管理员、目标群及当前归属；若读取后归属变化，拒绝发送旧邮箱。发送前先持久记录尝试，确认飞书回执后记录消息 ID；发送结果不明或重启留下“尝试中”时，**全部群表自动发布暂停**，管理员需先到目标群核对，不能靠重启或再次点启用绕过。现版没有自动清除此状态或扫描群历史重建消息 ID 的能力，需受控人工处理。平台读取失败后至少等待约 15 分钟再尝试，避免每分钟反复打接口；存储故障则关闭发布、保留原件，不作自动修复。存储损坏或达到 32 MiB 上限时群发布关闭且保留原件。该密文不进入 Git，也不能跨电脑直接解密。

飞书消息使用现有应用身份：`POST /open-apis/im/v1/messages?receive_id_type=chat_id` 仅发送到当前绑定群；后续 `PATCH /open-apis/im/v1/messages/{message_id}` 更新同一张非交互卡片。卡片仅含纯文本，禁转发、无表单或按钮。消息发送/更新失败不保留完整服务端异常；群里看到的实际渲染、旧卡片更新可用期和应用权限须在真实小范围验收。**本地隔离测试只证明代码和模拟回执，不证明正式群已收到或结算金额正确。**
