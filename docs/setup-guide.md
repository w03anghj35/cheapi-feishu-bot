# 飞书机器人完整搭建、配置与换机手册

适用于本仓库 Windows 桌面管理端。文档整理日期：2026-10-29；后台菜单、审核规则和客户端支持可能变化，以当前飞书后台和实际验收为准。

**这里说明密码和密钥怎么获取、填写、保存，不提供任何真实密码、App Secret、Cookie或令牌。没有通用的默认管理员密码。** 不要把敏感值写进 GitHub、截图、聊天、命令行或提交记录。

## 0. 先选对路线

| 您的情况 | 应该怎么做 |
| --- | --- |
| 原机器人已经在群里，只想换一台常开电脑 | 保留同一个飞书应用、App ID、机器人和原群。先读第1、2节，再按第10节切换；不要新建第二个正式应用。 |
| 以前没有机器人，从零部署 | 按第1–9节顺序进行。 |
| 只想更新程序 | 先读第12节；不要把重新填写Secret当作日常更新步骤。 |

本工具的三条主要流程：管理员授权与配置；群成员私聊注册；群成员私聊创建令牌。它不依赖账号池、MySQL、phpStudy、Codex或AI接口，也不是全天候服务器服务。

## 1. 新电脑需要什么，浏览器能不能打开

### 1.1 随程序安装的工具与不会迁移的内容

| 工具/内容 | 下载仓库后是否自带 | 怎么准备 |
| --- | --- | --- |
| 管理页、客户页、飞书业务源码和测试 | 是 | 下载完整仓库并解压，不能只拿一个BAT。 |
| Electron / Chromium 内置平台登录窗口 | 安装后才有 | 安装Node.js，运行 `install.bat`，它会安装并校验Electron运行文件。无需另装Chrome。 |
| 飞书Node SDK等依赖 | 源码不带已安装包 | `install.bat`按两份锁文件安装。 |
| Node.js / npm | 否 | 安装Node.js 24 LTS（包含npm）。 |
| Git | 否；可选 | 下载ZIP不需要Git；使用git clone/pull时需要。 |
| 系统Edge、Chrome及其扩展 | 否 | 新电脑自行安装/使用；不是机器人运行依赖。 |
| Codex及其Browser／浏览器插件 | 否 | 它属于Codex环境，不在本项目依赖里；如另有需要，按Codex当前官方界面配置。机器人不靠该插件登录、收消息或运行。 |
| 旧浏览器Cookie、平台管理员登录态、App Secret | 否 | 新机亲自重新登录、输入凭据，不能期待GitHub恢复登录。 |
| 创建记录、管理员/群绑定、分组别名、安全策略 | 否 | 新机重新配置；旧历史保留原件，不在GitHub传输。 |
| 原飞书应用、已发布机器人、原群 | 属于飞书云端，不是本机文件 | 同一应用继续使用，是否可用仍取决于发布范围、权限和客户端。 |

**结论：新电脑装完运行环境后，项目自己的登录浏览器可以打开；不需要复制旧电脑的整个浏览器或修复Codex Browser插件。** 已验证的是本机干净克隆和隔离Electron窗口，不是每一台实体新电脑的网络、登录和手机兼容性。

### 1.2 内置浏览器的边界

源码 `key-tool/main.js` 使用Electron `BrowserWindow`，平台登录分区为 `persist:cheapi-key-login`，入口为平台 `/keys`。浏览器只允许平台同源导航，拒绝另开窗口，并禁用页面Node能力与权限请求。

它是**受限的平台登录窗口，不是通用浏览器**。在系统Chrome登录不等于工具已获得授权；依赖跨站跳转或新窗口的SSO登录也未保证支持。遇到登录失败先核对网络、实际登录方式和本机提示，不要为方便关闭安全隔离或复制Cookie。

## 2. 密码、密钥、验证码分别是什么

| 项目 | 来源与用途 | 填写位置 | 保存与换机要求 |
| --- | --- | --- | --- |
| 飞书登录账号/密码或扫码 | 管理员本人登录飞书客户端和开放平台 | 飞书官方登录界面 | 不填入机器人源码；新机按飞书正常登录。 |
| 飞书 App ID | 开放平台 → 既有应用 →「凭证与基础信息」 | 管理页「飞书 App ID」 | 不是密码；换机使用原应用的值，不能借用另一个应用。 |
| 飞书 App Secret | 与App ID同页，由应用管理员查看/复制 | 管理页「App Secret（仅本机输入）」密码框 | 本机Electron安全存储加密；新机重新输入。不要发送给维护者或群成员。 |
| 平台管理员账号/密码 | 平台已有管理员账户，由管理员管理 | 点击「登录／重新授权」后出现的内置平台登录窗口 | 本工具没有默认密码；不能使用普通客户账户代替。登录后回管理页保存授权，新机重做。 |
| 平台授权 | 内置登录后由工具验证并保存 | 「完成登录并保存」 | 受本机安全存储保护，可能过期/被平台撤销。不要从浏览器开发者工具拷贝token。 |
| 管理员绑定挑战 | 本机点击「绑定管理员身份」临时生成 | 管理员与机器人的私聊 | 5分钟有效，本次使用，不是App Secret。不要在群里发管理员绑定命令。 |
| 群绑定挑战 | 本机点击「绑定 2API 目标群」临时生成 | 准确目标群中 @机器人后发送 | 5分钟有效；还需回本机确认准确群，不可复用旧码。 |
| 注册用户的密码 | 注册者自己新设的专用密码 | 机器人私聊的注册卡片输入框 | 不回显、不写本机业务账本；仍经过飞书处理，遮挡不代表第三方零留存。不要使用重要账户的复用密码。 |
| 创建后的令牌密钥 | 平台实际创建成功返回 | 只给发起人私聊，附平台网址 | 不是管理员登录密码；不得发群里或提交GitHub。未收到不能盲目重试创建。 |
| GitHub登录/访问授权 | 有权访问本私有仓库的GitHub账户 | GitHub网页或Git凭据管理 | 与飞书、平台密码完全独立，不要把访问令牌写进仓库URL。 |

### 如何安全填写App Secret

1. 打开 [飞书开放平台](https://open.feishu.cn/app)，进入**原应用**，左侧找到「凭证与基础信息」。
2. 确认App ID属于要服务的那个机器人，查看/复制App Secret。
3. 回到本机业务管理员窗口，向下找到包含「本机连接／管理员身份／目标群／2API账户绑定／群内申请」的飞书区域。App ID旁边就是 **App Secret密码框**。
4. 亲自粘贴到该框，点击「加密保存飞书配置」。不要粘贴到PowerShell、聊天、GitHub或普通配置文件。
5. 核对保存提示，再清除剪贴板中的敏感内容。截图前把框和身份信息遮挡。

已保存后密码框不会回填原Secret，空白不能单独证明保存失败。用本机提示和连接结果判断。**再次保存凭据会关闭群策略并清除旧管理员/群绑定，需要重新绑定；它不是「刷新状态」按钮。**

本项目不要求填写Webhook的Verification Token或Encrypt Key；它们不能代替App Secret。也没有需要配置的MySQL root密码。

## 3. 从零创建飞书应用并设置权限

**已经有正式应用、只换电脑的管理员跳过本节的创建操作。** 需要排障时只读核对原应用设置。

### 3.1 创建自建应用并添加机器人

1. 在自有企业的飞书开放平台创建企业自建应用，填写名称和用途。
2. 在「添加应用能力」添加「机器人」，设置合适的机器人名称和说明。
3. 在「凭证与基础信息」确认App ID与App Secret；只在管理员本机填写，不在文档记录真实值。
4. 如正式群含外部成员，检查当前后台是否提供「应用共享／外部群使用／外部用户单聊」等设置，按官方条件配置；入口名称和是否支持取决于企业及应用状态。

### 3.2 消息权限

当前实现使用的最小消息能力对应以下权限标识（中文名称以当前后台为准）：

| 权限标识 | 本项目用途 |
| --- | --- |
| `im:message:send_as_bot` | 机器人身份发送菜单、私聊卡片和结果。 |
| `im:message.p2p_msg:readonly` | 接收用户私聊及管理员绑定命令。 |
| `im:message.group_at_msg:readonly` | 接收目标群中 @机器人的消息。 |

在「权限管理」搜索并申请这些能力；如果添加事件时后台提示关联权限，一并按其当前说明核对。不要为了省事申请通讯录全读、全部群消息读取或其他无关管理权限。权限申请、管理员批准、版本发布生效是不同步骤，不能只保存草稿。

### 3.3 事件和卡片回调都要配置

| 后台区域 | 接收方式 | 添加内容 |
| --- | --- | --- |
| 事件与回调 → 事件订阅/事件配置 | 使用长连接接收事件 | 接收消息 `im.message.receive_v1` |
| 事件与回调 → 回调配置 | 使用长连接接收回调 | 卡片交互 `card.action.trigger` |

源码 `feishu-connection.js` 同时注册这两个处理器。**只配消息事件会导致有菜单却点按钮没反应；只连诊断工具也不能处理注册/创建。**

某些后台保存长连接设置前需要在线连接。此时先完成第4–6节的业务工具安装、平台授权与凭据保存/连接，再回后台保存事件和回调，最后发布。连接可以先建立，正式群申请仍保持关闭。不要另开诊断实例与业务实例竞争同一应用。

该方案由电脑向飞书建立出站长连接，不需要公网回调URL、内网穿透或自行开放入站端口；仍需本机正常访问平台、飞书HTTPS及长连接服务。卡片回调不是本地随便填写一个HTTP地址。

## 4. 安装并启动本机业务工具

1. 从 [本私有仓库](https://github.com/w03anghj35/cheapi-feishu-bot) 下载ZIP并解压到固定目录，例如 `C:\Tools\cheapi-feishu-bot`；或者在已安装Git且有访问权限时克隆。
2. 安装 [Node.js 24 LTS](https://nodejs.org/)，重新打开终端，执行 `node --version`、`npm --version`确认可用。
3. 双击仓库根目录的 `install.bat`。需要联网下载两组锁定依赖和Electron运行文件，首次不一定很快。
4. 安装完成后双击 **`启动飞书机器人.bat`**。它打开业务管理员窗口。

对应命令（在仓库根目录执行，失败先处理，不跳过安装步骤）：

```powershell
npm ci --no-audit --no-fund
npm run deps:bot
npm run runtime:install
npm run check
npm test
npm start
```

若PowerShell限制 `npm.ps1`，可以调用同安装自带的 `npm.cmd`（如 `npm.cmd start`），不必全局降低脚本执行策略。启动脚本已为普通Windows操作提供入口。

- `启动客户令牌工具.bat` 是客户工作台，不是首次管理员配置入口。
- `飞书连接诊断.bat` 只诊断连接，不回复正式业务、不创建账号/令牌。
- 根目录和 `key-tool` 各有依赖锁；只装其中一份不完整。
- 源码仓库不含旧exe、node_modules或浏览器运行二进制。`install.bat`完成后再启动，不复制旧机node_modules。
- 提示Electron运行文件缺失时，先运行 `npm run runtime:install`；安装有单次5分钟超时，失败不会冒充成功。不要并行反复点多个安装或测试。

## 5. 登录平台管理员并发布客户分组

1. 管理页顶部点击「登录／重新授权」。程序会打开内置平台窗口。
2. 管理员亲自在 [平台](https://max.cheapi.cc/) 登录管理员账户。不向客户展示管理员密码，也不需要客户进入平台管理员登录。
3. 回到管理页点击「完成登录并保存」，确认显示的实际管理员账户正确且授权可用。系统浏览器已经登录，并不能代替本步骤。
4. 点击「重新读取平台分组」。
5. 给允许客户使用的原始分组填写**客户显示名称**，点击「保存并更新客户分组 ↗」。未命名的分组不提供给客户选择。

客户别名不改变平台原始分组，不靠名称猜分组ID。读取分组失败先检查授权，不要把未完成登录当成平台没有分组。日后授权过期需重新登录，不把授权写死进源码。

只有出现明确解密错误时，才考虑界面提供的「保留原件并恢复授权」，并保留原文件；它不是日常登录按钮。不要删掉账本或加密文件来消除错误。

## 6. 保存飞书配置，绑定管理员和唯一目标群

### 6.1 保存和连接

1. 在第2节说明的密码框填同一应用的App ID和App Secret。
2. 点击「加密保存飞书配置」，确认保存提示。此时群申请默认关闭，旧绑定清除。
3. 点击「连接飞书」，等待「本机连接」显示已连接。保存成功不等于已连接。
4. 连接失败核对是否混用了其他应用的Secret、网络是否可用、同机是否另开诊断连接。不要反复重置Secret试运气。

业务工具与独立诊断工具使用不同加密上下文，诊断连接成功不代表业务工具已有可读配置。请在**业务管理页**保存，而不是复制诊断工具的密文文件。

### 6.2 管理员绑定

1. 点击「绑定管理员身份」。
2. 从当前管理窗口复制**本次完整命令**，仅由管理员本人私聊机器人发送。格式为 `/绑定管理员`，后接空格和本次动态挑战码；不要发送文档占位文字。
3. 5分钟内回到本机，核对候选身份，点击「确认此管理员」。

挑战不是固定密码，不要让同事代发，不在群中发。过期后重新生成本次挑战。

### 6.3 目标群绑定

1. 在飞书将原机器人加入实际要服务的群。如果搜索不到，先完成第7节发布/范围检查。
2. 本机点击「绑定 2API 目标群」。
3. 管理员在**准确目标群** @机器人并发送窗口本次显示的完整命令。当前命令是 `/绑定机器人`，后接空格和动态挑战码，不是「绑定管理员」。
4. 回本机核对候选群，确认与实际目标群一致，再点击「确认绑定此群」。

本版本只绑定一个群；不要为了通过测试绑定一个临时群后以为原群已可用。绑定未完成不应该开启群申请。

### 6.4 安全策略与启用

按当前已确认需求填写：

- 单次最高额度：**20**，单位与平台一致。
- 每人每日最高额度：**留空**，代表无限制，不是填0。
- 全群每日最高额度：**留空**，代表无限制，不是填0。
- 确认管理员、目标群、平台账户匹配，勾选「允许此群所有成员使用」，点击「保存安全策略」。

单次20不等于全日最多20；两个日上限不限意味着没有日累计额度保护。已绑定群全员可用，不代表任意其他群也可用；飞书云端的外部单聊/可见性也不会被本机开关绕过。

## 7. 飞书版本发布、范围和群内安装

**首次部署需要发布；单纯换电脑不需要重新建应用或仅因换机发布新版本。** 若修改权限、能力、可见范围、共享配置等，按当前飞书后台要求发布/批准相应变更。

1. 回开放平台，核对机器人能力、上述权限、消息事件及卡片回调均已保存。
2. 在「版本管理与发布」创建版本，填写版本号和简明更新说明。
3. 设置应用可用范围，覆盖目标群里的预期使用者。当前目标不是只给所有者本人或少数测试成员；按企业实际成员范围配置，避免扩到无关用户。
4. 如果目标群里有只入群、没加入企业的外部用户，还要核对外部群使用、外部用户单聊及首次授权/确认条件。**企业内部「全员」不等于所有外部群成员自动有权限。** 不支持的场景须按飞书当前官方规则处理。
5. 提交发布，完成企业管理员审核（如需要）。在**已发布版本**详情核对状态、权限、可见范围、共享设置；「保存成功／待发布／审核中」都不是发布完成。
6. 在目标群的机器人管理入口搜索并添加该应用机器人（若已在群内则不重复添加）。然后继续第6节绑定和第8节验收。

仅看到本机「已连接」，不能证明已发布、收得到事件、外部成员能私聊或手机卡片可显示。文档没有实时读取您当前租户后台，不能凭本文判定当前发布状态。

## 8. 用户怎么用，以及怎么验收

### 8.1 群入口和菜单

群成员在已绑定群 @机器人，机器人私聊发送菜单：

1. **用户注册**。
2. **令牌创建**。

也支持「发送令牌／申请令牌／创建令牌」等快捷入口。首次私聊可能需要在飞书客户端完成开启单聊/授权确认；卡片是否显示还受客户端与成员身份影响。

### 8.2 用户注册

私聊点「用户注册」，在原生卡片填写：

- 账号邮箱：有效邮箱，最长254字符。
- 密码：至少8字符、最多72个UTF-8字节，不能全空白或含控制字符。使用新设专用密码；普通空格会原样保留，不自动trim。
- 用户名：1–60字符，不含控制字符。
- 并发数：整数1–50。
- 初始余额：只能选 **0、1、5、10**。

角色固定普通用户（user），RPM限制为0（界面表示不限）；不允许用户把自己改成管理员。提交表单后先看无密码的核对页，再最终确认一次。

**注册初始余额和令牌额度是两个业务字段。令牌单次上限20不会自动限制注册余额累计。当前没有「每人终身只能注册一次」或注册余额每日累计限制，不能当成已有保护。**

### 8.3 令牌创建

选择管理员已发布的客户分组 → 填额度 → 核对并确认一次。成功结果私聊包含分组、额度、**平台网址和完整令牌密钥**，不在群里发送密钥。

申请会话10分钟有效；当前短时入口限制为每个身份5分钟最多3次。切换电脑、重启、会话过期或旧卡片不可用时，重新 @发起，不继续点旧卡片。

### 8.4 管理员验收清单

- [ ] 平台授权可用，实际账户正确，客户分组别名已发布。
- [ ] 本机连接在线；管理员身份、目标群、2API账户绑定、群内申请均符合预期。
- [ ] 已发布版本包含消息事件、卡片回调和目标成员范围，不是只看草稿。
- [ ] 由一位实际群成员 @，收到私聊菜单；外部成员与iPhone/安卓分别测试，不能只测应用所有者。
- [ ] 注册卡片可填、核对页不回显密码；真实注册只按实际需要确认，之后对照平台用户列表。
- [ ] 令牌按实际需要确认一次，私聊同时有网址和密钥，平台最终状态与本机记录一致。
- [ ] 报错只反馈安全错误编号、时间、功能和设备版本，不反馈密码、密钥或完整响应。

不要为了「验收」连续创建无用账号/令牌。创建超时、unknown、pending先核对平台权威状态，不能把没收到私聊当成没创建。

## 9. 常开运行和数据存放

电脑关机、休眠、注销、应用退出或网络中断时，用户仍可能在飞书发出 @，但本机业务机器人无法正常及时处理。恢复后旧事件/旧卡片不保证可续接。

- 需要电脑开机、接电不休眠、网络稳定、业务工具保持运行，并确认长连接在线。
- 锁屏通常不影响；关闭客户主窗口会退出整个应用，不能以为关闭窗口后仍是后台服务。
- 当前没有Windows服务、自动开机连接、跨机协调或高可用保障。开机启动脚本不等于已连接和已启用。
- SDK有受控重连及连接截止，不保证任何网络故障都无限自动恢复；断开后检查本机状态和安全提示。
- 本手册不会创建开机/关机任务，也不自动修改系统电源设置。

本机数据位置（不要上传）：

```text
%APPDATA%\CheapiKeyStudio
%APPDATA%\CheapiKeyStudio\feishu-business
%APPDATA%\CheapiKeyStudioFeishu
```

分别涉及业务数据/平台登录分区、业务飞书凭据以及诊断/策略/连接锁等。Windows安全存储受用户/电脑/入口环境约束；不要直接编辑加密文件，不凭文件存在就宣称备份可恢复。

## 10. 换到另一台电脑，仍用同一个飞书机器人

详细切换和回退见 [迁移手册](migration.md)。关键顺序如下：

1. 新机先下载完整仓库、安装Node及依赖、运行离线测试；此时不要连接正式应用，旧机可继续服务。
2. 记录分组客户别名、策略、准确目标群；准备原App ID和Secret及平台管理员登录权限。不把这些秘密上传仓库。
3. 暂停新申请，等待正在执行的请求结束。旧机有pending/unknown先保留原件并只读核对；空的新机账本不能证明旧请求没创建。
4. **正常退出旧机业务工具，确认连接关闭，才在新机连接。** 同一App ID的多机连接不能当作可靠负载均衡，本机锁挡不住另一台电脑。
5. 新机启动业务管理端，重新平台登录并保存授权、发布客户别名，重新填写原飞书凭据、绑定管理员与原群、设置策略并启用。
6. 按第8节验收。未完成申请重新发起，旧卡片不跨机续用。
7. 保留旧机程序和原始数据，不急着删除。新机不会从GitHub取得旧创建记录、加密回执或额度累计；本仓库没有历史账本迁移器。

若新机失败，先停新机、保存并核对新产生的记录，再考虑恢复旧机；有新业务时不能盲目回旧账本继续发放。

## 11. 常见问题速查

| 现象 | 检查与处理 |
| --- | --- |
| 找不到App Secret或密码框 | Secret在飞书应用「凭证与基础信息」；填写框在本机**业务管理员页**飞书区域，必要时向下滚动。不是平台注册卡片或系统浏览器设置。 |
| 下载后BAT打不开／没有浏览器 | 确认完整解压、Node/npm可用、`install.bat`完成。Electron二进制缺失先 `npm run runtime:install`；不去修Codex插件。 |
| 内置登录窗口打不开网页 | 核对实际网络、平台可达性和工具提示；系统浏览器能访问不代表Electron登录分区正常。跨站SSO/另开窗口未保证支持，勿关闭隔离绕过。 |
| Node/npm找不到 | 安装Node.js 24 LTS并新开终端；`npm.ps1`被限制可用 `npm.cmd`，不要全局解除执行策略。 |
| 已登录系统浏览器，工具仍未授权 | 用工具「登录／重新授权」打开内置窗口，完成后回管理页「完成登录并保存」。 |
| App Secret框重开为空 | 不回填秘密是设计。先看保存/连接状态，不要反复保存导致绑定被清除。 |
| 独立诊断显示已连接，群里无回复 | 诊断入口不处理业务。停诊断，使用业务管理端配置；继续核对平台授权、发布状态、绑定与群策略。 |
| 本机已连接，群 @没有菜单 | 检查消息事件/权限是否发布、目标群是否精确绑定、账户匹配及群申请是否启用；不要只看连接标签。 |
| 菜单有了但按钮无反应 | 核对 `card.action.trigger`、回调长连接和发布状态；只用最新有效卡片，确认不是旧会话或诊断程序。 |
| 找不到机器人或某些同事打开失败 | 核对已发布范围、是否外部成员、应用共享/外部群/单聊条件和首次确认；不能只用所有者成功推断全员可用。 |
| 某些iPhone「加载失败，点击重试」 | 记录飞书版本、iOS版本、内外部身份、发生时间；分别测客户端入口和私聊卡片，对照已发布设置。不能无证据断定是密码、机器人离线或所有iPhone不支持；该同事问题仍需设备实测。 |
| 加密配置无法解密 | 不复制其他入口/电脑密文，不删除历史记录；保留原件，使用受支持的重新授权流程，Secret在本机重填。 |
| 创建失败/超时或没收到密钥 | 记录安全错误编号，查本机创建记录和平台最终状态。unknown/pending保持保护，先只读精确核对，不重放POST、不自动重发密钥。 |
| Git克隆/更新失败但网页能访问 | 核对Git自己的代理和凭据。不要把GitHub token放URL或临时关闭TLS校验；网络问题不靠删除业务数据解决。 |
