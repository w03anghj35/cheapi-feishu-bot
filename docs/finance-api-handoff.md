# 财务处理结果接口说明（本机接入版）

核对日期：2026-11-12。此文档区分**已实现的本机只读 HTTP 接口**与**尚缺数据源的财务指标**。同事只消费处理后的 JSON，不应获得平台 Bearer、飞书 Secret、渠道 Cookie 或 Electron 管理员 IPC。代码在原 Windows 管理端内运行；首次启用前不监听端口。

## 启用与调用边界

管理员在「07 渠道监控」展开「本机只读财务接口」，确认平台管理员授权后点击「启用本机接口」。只监听 `127.0.0.1:5191`；端口冲突时失败关闭，不自动改绑公网。独立的 32 字节随机访问密钥由 Windows 安全存储加密保留，页面及操作日志不回显；管理员明确点击「复制访问密钥」才会写入本机剪贴板，60 秒后若仍为该值则清除。可暂停或轮换，轮换后旧密钥失效。不要把密钥放入聊天、源码、网址、日志或前端网页。首次升级默认关闭；已启用配置重启时仅在原平台管理员授权核验成功后恢复，否则保持不监听、待管理员处理。

所有路由均为 **GET**，请求头 `Authorization: Bearer <本机独立访问密钥>`；不使用 Cookie，也不允许浏览器跨域调用。固定地址如下：

| 路由 | 已实现的结果 | 刷新方式 |
| --- | --- | --- |
| `GET http://127.0.0.1:5191/v1/finance/channel-balances` | 五个供应商的来源金额、各自倍率、人民币折算及渠道总余额 | 读取本机最近一次监控状态；不会因此重新登录或强制刷新外站 |
| `GET http://127.0.0.1:5191/v1/finance/customer-balances` | 全平台普通用户正余额合计、负余额单列、管理员排除数 | 每次完整读取用户目录；同一时刻只准一次，完成后至少间隔 5 分钟 |
| `GET http://127.0.0.1:5191/health` | `{"status":"ok"}` | 仅说明本机接口在响应，不保证五站或平台数据可用 |

接口统一返回 `Content-Type: application/json`、`Cache-Control: no-store`。金额均为十进制**字符串**，不能用前端浮点数二次求和。`401` 为缺失/错误密钥，`403` 为不符合本机 Host 或带网页 Origin/Referer，`404` 为未知路由，`405` 为非 GET，`429` 为并发/冷却（带 `Retry-After`），`503` 为来源、授权、配置或时效无法核对；错误体只给固定 `error` 代码，不返回密钥或原始响应。`429` 可按 `Retry-After` 稍后再读；`503` 应由管理员核对来源，不能静默用旧金额或零替代。客户目录最多 50 页/5000 用户，分页不完整时整次返回 `503`；接口 125 秒超时，超时后源请求可能仍在收尾，期间继续拒绝重叠查询。

**部署限制：** 这不是公网 API。同事的网站若部署在另一台机器，它访问自己的 `127.0.0.1` 不会连到本机。最终要把本项目的计算/采集服务作为受保护的后端组件部署在可运行 Electron 采集的环境，或另行设计经认证的安全转发。切勿通过直接开放 `0.0.0.0`、端口转发或把本机密钥放进浏览器 JavaScript 来跨机接入。当前只完成本机接口与合成测试，尚未验证同事服务器的远程联通。

## 已实现：五渠道折算余额

原管理端「07 渠道监控」每张卡片增加独立的“人民币折算倍率”和“保存倍率”。倍率是**每 1 单位该站页面数值折合多少人民币**，由管理员显式填写，默认不设；最多 8 位小数，范围 `(0, 1000000]`。倍率存于当前 Windows 用户的独立 `channel-monitor/channel-monitor-factors.journal`，不改原站登录凭据或原始余额。每卡显示原金额、倍率和折算人民币金额，底部显示「渠道总余额（折算人民币）」。

纯计算入口是 `key-tool/finance-metrics.js` 的 `calculateMonitoredSuppliers(channelRows, factorState, options)`；管理员页面使用 `channelConvertedState()` IPC，本机 HTTP 的 `/v1/finance/channel-balances` 复用同一计算，不要求同事重新实现公式。HTTP 只输出投影，不公开 IPC 或渠道登录凭据。

处理结果字段：

```json
{
  "status": "ready",
  "asOf": "2026-11-12T04:00:00.000Z",
  "suppliers": [
    {
      "channelId": "points-ip",
      "supplierId": "points-ip",
      "name": "虚构渠道甲",
      "sourceUnit": "points-ip",
      "amount": "100.5",
      "cnyPerUnit": "1.6",
      "convertedCny": "160.8",
      "status": "ok",
      "reason": null,
      "successAt": "2026-11-12T03:59:00.000Z"
    }
  ],
  "totalCny": "...",
  "missing": []
}
```

示例只显示一个**虚构**供应商，正式返回必须有五个固定 `channelId`。`sourceUnit` 使用固定渠道 ID 表示“该站页面数值”，不是声称积分、USD、CNY 是同一物理币种；管理员给每站的 `cnyPerUnit` 才是换算依据。`supplierId=channelId` 是用户当前确认的“渠道即供应商”口径；若将来同一供应商有多渠道，需另建显式映射并防重复计入。

`totalCny` 仅在五站的 `status=ok`、最近一次成功读取不超过 1 小时、原始金额可精确解析且每站倍率已配置时为十进制字符串；否则 `status=missing,totalCny=null`，`missing` 逐站列原因。失败卡片的旧 `display` 不参与合计。刷新界面或 IPC 查询**不会自动强制外站重新读取**；数据时效以 `successAt` 判定。页面右侧五站余额仍各自显示，QQ 低余额提醒继续按原始单位阈值判断，不受折算倍率影响。

金额计算使用定点整数：来源最多 12 位小数，倍率最多 8 位；各站折算到人民币 8 位小数后再合计。客户端不得改用 JavaScript 浮点数求和；接口使用字符串传金额。

## 已有客户余额读取，财务口径已按用户确认调整

原「用户余额」读取固定 `GET /api/v1/admin/users?page=N&page_size=100`，完整 50 页/5000 用户且管理员前后复核后，按用户确认的业务口径把 `balance` 视为人民币：仅 `role=user` 的**正余额**计入客户负债，启用、停用、未激活的普通用户都计；全部 `role=admin` 排除。普通用户负余额的金额与人数**单列**，不抵减正余额。平台用户目录未逐人声明币种，因此此 CNY 是当前业务约定，应由财务在联调时确认。金额按 8 位定点十进制字符串输出，不用“归属档案中已勾选用户”代替全平台普通用户。

财务提供的现金接口尚未接入。本项目未来只对**该财务接口的 U 余额**使用经管理员确认的 U→CNY 倍率（目前口头规则 6.65）；**不能对平台客户余额整体乘 6.65**。

本机 `GET /v1/finance/customer-balances` 返回示例（虚构数值）：

```json
{
  "status": "ready", "asOf": "2026-11-12T04:00:00.000Z", "currency": "CNY",
  "positiveBalanceCny": "120.5", "negativeBalanceCny": "-3.2",
  "positiveCount": 2, "negativeCount": 1, "excludedAdminCount": 1,
  "scannedUsers": 4, "complete": true
}
```

只返回汇总，不返回客户姓名、邮箱或逐人余额。由于目录逐页读取，`asOf` 是**核对完成时间**，不是上游数据库的原子快照时间。

## 今日 / 本月经营：数据契约已厘清，完整接口尚未实现

管理员页面 `/admin/usage` 的“总消费”对应平台统计 `total_actual_cost`（消耗收入）；其下橙色“成本”对应 `total_account_cost`（平台账号计费口径）；灰色“标准”对应 `total_cost`，不得拿它代替橙色成本。上游公开源码的账号成本按 `(account_stats_cost ?? total_cost) × (account_rate_multiplier ?? 1)` 累加为 `total_account_cost`；这仍是平台计费口径，不自动证明与供应商最终账单一致。当前原项目的 `finance-usage-source.js` 已为**单个用户、单个北京自然日**提供受控 GET 适配器，成本字段缺失返回 `null`，不补 0 或回退标准值。

一手参考：上游 `frontend/src/components/admin/usage/UsageStatsCards.vue` 的三项展示字段，以及 `backend/internal/repository/usage_log_repo_stats.go` 的账号计费聚合逻辑（2026-11-12 只读核对）。`max.cheapi.cc` 的当前登录后统计响应尚须现场对照，不能仅凭上游 main 断言每个筛选条件都返回成本。

拟输出：`revenue`、`platformAccountCost`、`grossProfit=revenue-platformAccountCost`、`grossMarginPercent`；收入为 0 时毛利率 `null`。今日和本月分别返回覆盖范围、读取时间和完整性。按客户使用稳定平台 `user_id`；市场人员按用户确认的“归属姓名”及按日生效链；渠道/供应商按用户确认的“渠道即供应商”，但平台使用日志的 `channel_id/account_id` 与五个余额站 `channelId` **尚无已核验的映射**，不能凭名称猜配。未归因项必须单列。当前全量明细、映射、周期覆盖及跨来源对账均未完成，因此今日/月经营接口不可标为已上线。

## 自由现金：公式确定，现金来源待接入

公式：`自由现金CNY = 财务现金CNY + 渠道总余额CNY − 普通用户正余额CNY`。普通用户负余额单列，不参与扣减；管理员余额不计。当前 `finance-metrics.js` 已有定点纯计算和 `missing_inputs` 状态，但财务现金接口和 U→CNY 折算、跨来源时间对齐尚未接入，所以不提供实数结果。任何输入未取得或过期，`valueCny=null`，不能用旧余额、0 或猜测汇率凑数。

## 对接与安全边界

原 Electron 内部 IPC 仍仅供本机管理员界面使用；上述 HTTP 是另加的最小包装，不会把 IPC 向公网开放。本机 API 密钥只证明**同一台电脑上的受信任后端调用者**，不等同于同事网站的老板登录/角色鉴权。若将服务迁入同事仓库，需在其后端验证老板权限、关联正确平台管理员与来源范围，并在部署处重新建立渠道登录会话；Windows 加密的旧会话不能直接复制到服务器。HTTP 请求无需携带客户 ID，客户端不得据此推断逐人数据。接口不存客户余额快照，历史报表仍以原独立账本为准。
