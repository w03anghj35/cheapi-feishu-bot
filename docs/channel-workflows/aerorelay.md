# AeroRelay：剩余余额

- 站点：`https://vip.aerorelay.one`；目标页：登录后实际`/dashboard`。原`/usage`未登录时可能显示公开首页，点登录再进入业务仪表盘。
- 指标：剩余可用余额，用户于2026-11-03确认选此口径；不是“今日消费”，也不是之前要求的累计“总消费”。
- 页面组件：实际已登录仪表盘显示“余额”及“可用”，旁有货币金额；同页还显示“今日消费”和其他费用，应只按“余额/Balance/Available Balance”标签提取唯一金额。
- 旧失败：监控固定访问`/usage`，将短暂公共首页判断成“待登录”，而本机业务仪表盘仍保持登录。修正入口到`/dashboard`并要求连续三次登录态观察再报告待登录。2026-11-03复发条件：用户手动登录后，隐藏窗口的“立即读取”仍强制重载；SPA短暂公共首页持续超过三次采样，旧的`formUnavailable`标记立即把页面判为“自动登录表单未识别”，虽然网站窗口已显示`/dashboard`和“余额”。
- 代码定位：`key-tool/channel-monitor.js`稳定内部ID`spent-aerorelay`保留旧名只为复用持久浏览器分区；`metric`和`path`已更新为余额。`channel-monitor-host.js`控制页面加载与登录确认。
- 登录恢复：公开登录表单使用`#login-email`、`#login-password`、`#login-submit-btn`，同源`POST /api/v1/auth/login`提交邮箱和密码；成功后站点自己保存访问/刷新令牌。公开`/admin/`前端有`POST /api/v1/auth/refresh`与401后续期逻辑，失败会清会话并跳回登录。网页脚本只作结构依据，不采集真实令牌或完整响应。2026-11-03观察到实际窗口回到登录表单，故持久分区不等于永久登录。
- 2026-11-03本地增量：第七栏目此站原有可选本机加密凭据已保留，并扩展为四站独立配置；AeroRelay原加密文件路径不变。`channel-login-store.js`负责安全保存、提交前持久占用、成功后恢复、失败暂停及清除；`channel-monitor-host.js`仅在隐藏窗口、HTTPS同源、指定路径及已核对的表单结构下提交一次；随后确认业务页，不绕验证码、MFA或证书警告。任何改版先重新核对表单和站点自己的登录流程，再改对应定位器及隔离夹具。密码不进入页面定位台账。
- 本地修复：针对管理员主动“立即读取”且前次有表单未识别标记、当前窗口已在`/dashboard`的恢复场景，先读现有页面、不再次重载；只有稳定两次读到目标金额才清除标记。普通后台定时读取仍可重载以取得新数据。AeroRelay登录态采样由3次延长为8次，以容纳较慢的SPA过渡；真实登录表单仍限同源、指定结构及一次提交。
- 验证：用户已在新版本机保存可选加密凭据并亲自登录；可访问性只读核对网站仪表盘显示“余额/可用”，但在线监控卡片在点击“立即读取”后仍报“自动登录表单未识别”。修复的定向合成回归通过，**尚未再次换版，也未确认真实监控读数或长期自动登录**。网站会话是否长期有效取决于服务端，不能承诺永久免登录。
